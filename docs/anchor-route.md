# Anchor route (anchor_route.py)

The vocabulary eval left three gaps that no generator setting closed. Generated gunshots rise in 7 to 16 ms where real close shots rise in about 1 ms, die within about 100 ms where real ones ring for about 300, and sit on a -75 dB floor where real recordings carry room tone near -40 dB. Breaking glass reaches 0.06 of the real judge rate. Footsteps on wood, stone, grass and metal reach 0 to 0.15 of real, with gravel the one surface that passes. Each of those is a property a real recording already has, so the anchor route asks a narrow question: if Stable Audio 3 starts from a real recording retrieved for the key, partly noised through `init_audio`, does the output keep the real attack, tail, room and material while still being a new sound? `scripts/bench/anchor_route.py` answers it with numbers on the GPU, and the copying measurements decide whether the answer counts as generation at all. A route that scores well because it plays the library back is a sample player, and the report is built to show that case plainly.

## Patent caution

## Anchor pool

The pool is the training and anchor pool the held-out track defines in `scripts/bench/heldout_sources.json`, the file `vocab_refs.py --heldout` writes. The script reads that file by its schema, the way `scripts/train/encode_latents.py` does. A clip may anchor only from an uploader in `foleyset.uploaders` or a gun in `c3gd.guns` whose `pool` is train; a source the file holds out or never lists stays out. Within those sources a FoleySet clip counts when FoleySet puts it in split train, and a C3GD clip when it is split train on DAVE at oh_farm (7 m, unclipped, mono, the file's `meta.train_mic`). Split val stays out because the file keeps it for early stopping, and a run that asks for other splits, mics or events against this file stops with a message. The file's `meta.manifest` (`data/refs_heldout/manifest.json`) becomes the eval manifest for the leak check and later for the score, and the run stops when that manifest is missing. The file also lists `train_clips`, the trainable clips that belong to a reference set. The script leaves that list alone: anchoring from it would hand retrieval a library already sorted into the eval's sound types, and it mixes in split val.

A sources file in another format goes through a generic walk. Lists under keys that name uploaders, usernames, platforms, guns, Freesound ids, C3GD file ids, clusters, sources or recordings become source sets, cluster strings in the manifest convention (`fs:<uploader>`, `c3gd:<platform>`) resolve by their prefix, and lists of clip records become clip lists. Anything nested under a key starting with held, holdout, eval, test, val, exclu, block or reserved is held out; anything under pool, train, anchor, library or allow restricts the pool. An explicit clip list under a pool key is taken as the pool, resolved by path, `fs_`/`c3gd_` id, FoleySet name or C3GD filename, with records under another pool and clips outside the anchor splits dropped. If the walk finds nothing it recognises, the run stops and prints the top-level keys. With no sources file at all, a built-in approximation runs: FoleySet train clips whose uploader has no clip in val or test, and C3GD train clips from DAVE at oh_farm minus every third gun of each form factor (`--c3gd-holdout-every`). The held-out track's rule differs in both halves (it holds an uploader out for a test clip only, keeps even that uploader when it carries more than 12 clips of one reference set, and holds out every second gun sorted by caliber plus every gun never recorded on DAVE at oh_farm), so the approximation suits smoke tests only. Some gun-level rule is needed either way, because C3GD splits clips within a recording file and every gun appears in train, val and test.

Whichever definition applies, more exclusions follow. ESC-50 audio never enters (CC BY-NC, evaluation only). As in `encode_latents.py`, a FoleySet clip is dropped when its Freesound recording also sits under `data/esc50` or `data/real_footsteps`, or when its uploader owns one of those ESC-50 files, which keeps the production footstep gate clean as well as the vocab references. Clips tagged ai-generated are dropped, so no anchor is another model's output. Any clip whose recording appears in the eval manifest is dropped. Missing and silent files are dropped and counted. After the audio check below, the pool is compared with the eval manifest once more. With a held-out manifest, any uploader, gun, recording or file shared with a reference, or any cluster the manifest lists as held out, stops the run before CLAP loads. With the old manifest the shares are printed. The JSON also reports, per eval type, how many library clips share an uploader or gun with that type's eval references.

Metadata exclusions are not enough, because FoleySet repeats recordings under different rows. Hashing the PCM frames of all 10,000 files gives 9,691 distinct recordings: 82 groups hold one recording under two to 23 rows (391 files), and 53 of those groups give the same audio different sub-categories, uploaders and splits. They sit almost entirely in Break/Drop, where one recording can be GlassBreak, PaperTear, IceBreak, BoneBreak and CanCrush at once; the clip first spotted in the dry run is ABouch's IceBreak `00976.wav`, byte for byte bdunis4's PaperTear `00510.wav`. So the pool drops any clip whose audio also exists in a held-out row, a val or test row or an eval reference, and keeps one copy of any recording repeated inside the pool. The PCM hashes are cached in `data/_gate/anchor/audio_md5.json` by path, size and modification time; the first pass reads every FoleySet file once, and later passes read none. The report prints the audit, including how many eval references fall inside mixed-label groups. In the old `data/refs/manifest.json`, 16 of the 41 FoleySet glass references do, a fifth of the 79-clip glass set, so the 0.06 glass ratio of the first vocabulary eval rests on a reference that may hold paper or ice. The held-out build now applies the same PCM rule (`AUDIO_RULE` in `vocab_refs.py`), and no reference in `data/refs_heldout/manifest.json` falls in a mixed group.

With the sources file of 2026-10-08 the pool is 5150 clips from 1292 sources: 4818 FoleySet train clips from training-side uploaders and 332 C3GD shots from the nine training guns. Of 5395 candidates, 55 went with uploaders of ESC-50 files, 21 with Freesound recordings ESC-50 also holds, 3 as ai-generated, 154 with audio identical to a held-out or eval clip and 12 as repeats inside the pool. Nearly all of the 154 are byte copies of files from held-out uploaders, and none copies a held-out reference. Before the audio step the count is 5316, the train pool of the LoRA track, so both routes draw on one set of recordings. A recomputation straight from the two metadata CSVs and the sources file finds every pool clip in split train from a training-side uploader, or on DAVE at oh_farm from a training gun, and no uploader, gun, recording or PCM hash shared with a held-out reference.

Every library clip is processed the way a generated clip is at the generation length: mono, `resample_poly` to 44.1 kHz, the 50 ms fade and zero padding that `vocab_refs.py` gives sources shorter than 1.0 s, `_extract` to 1.0 s, and `normalize_loudness` at `target_for("normal")`. That 1.0 s clip is the `init_audio` anchor. Cutting it with `_extract` to 0.6 s and levelling it again gives the kept version, which goes to CLAP and to every comparison, so anchors and outputs are always compared at the length that ships.

## Retrieval

Retrieval uses `laion/clap-htsat-unfused`, the CLAP the judges use. The audio encoder embeds every library clip at the kept length (resampled to 48 kHz by the judges' `_resample`), the text encoder embeds each key's SARGE prompt exactly as `build_prompt` writes it, and the top k library clips by cosine become that key's anchors (`--topk`, default 5). Variant v takes anchor v mod k, so 20 seeds spread evenly over five anchors and every anchor carries four seeds. Nothing in this path knows what a gunshot or a footstep is; a new key gets anchors the same way an old one does. Library embeddings are cached in `data/_gate/anchor/library_clap.npz` under a fingerprint of the processing and the CLAP name, so a second run embeds only clips it has not seen.

The retrieval table prints, for reading only, how often the top k carry the FoleySet sub-category or C3GD form factor of the key's real reference sets (`label`), the FoleySet category (`cat`), the key's surface in the tags for footsteps (`surf`), and an uploader or gun shared with the eval references (`eval`). Those shares come from the eval curation in `vocab_refs.py` and feed no decision; they exist so a bad anchor list is caught before anyone listens to what was built on it.

## Generation through init_audio

`StableAudioModel.generate` takes `init_audio=(sample_rate, audio)` and `init_noise_level`. A float32 numpy array is accepted directly: `numpy_audio_to_tensor` makes it one channel, `prepare_audio` zero-pads it to the padded sample count (1.0 s plus the 1.0 s production padding, rounded to the VAE chunk alignment: 90112 samples, 2.04 s, 22 latent frames of 4096 samples), duplicates it to stereo and encodes it. Sampling starts from `(1 - sigma) * anchor_latent + sigma * noise`, where the noise comes from `torch.manual_seed(seed)` before anything else, so a seed draws the same noise with and without an anchor. Each latent frame spans 93 ms of audio, which is why the replay control below matters: it shows how much of a 1 ms attack survives the encoder and decoder before any sampling happens.

The script calls `generate` through the production generator's pieces: `StableAudio3Generator(sampler_type="euler", steps=3)` with cfg 2.0, fp16, the accelerator and the prompt hoist, conditioning from `_inputs`, `_finish` for the 0.6 s `_extract` and the loudness, and a static guard that mirrors `_guard` but retries with the same anchor. The fast path keeps working: the CUDA graph keys on tensor shapes, which `init_audio` leaves alone, and the hoist sees `init_audio` in the call, skips its per-prompt cache and fills its slot once per call. The log prints the accelerator and hoist counters per setting, so an eager fallback would show. Plain clips at the current setting come from `generator.generate` itself, with the same seeds, as the baseline for both the judges and the copying nulls.

The installed schedule changes what a noise level means. small-sfx ships no sampling shift options, so `generate` uses the default `LogSNRShift(rate=0, anchor_logsnr=-6.2, logsnr_end=2.0)`. `build_schedule` shifts `linspace(sigma, 0, steps + 1)` and then forces the first entry back to sigma. With three steps that gives:

| init_noise_level | sigma per step |
|---|---|
| 1.0 (plain) | 1.0, 0.970, 0.676, 0 |
| 0.9 | 0.9, 0.949, 0.613, 0 |
| 0.7 | 0.7, 0.861, 0.478, 0 |
| 0.5 | 0.5, 0.676, 0.347, 0 |

At 0.5 and 0.7 the first Euler step climbs back toward noise, to 0.676 and 0.861, so the anchor keeps less than the nominal level suggests: level 0.5 passes through the same 0.676 that plain generation reaches at its third evaluation. The run records the schedule from `build_schedule` for each setting, which confirms or corrects these hand-computed values. `--schedules package scaled` adds a monotone variant through `generate`'s `dist_shift` argument, the plain schedule scaled to start at sigma (0.5, 0.485, 0.338, 0 at level 0.5); it is off by default so the main run matches the request.

Two more settings frame the levels. `raw` holds the retrieved anchors themselves at 0.6 s, so the judges score what perfect copying would earn. `replay` runs `init_audio` at noise 0.0, which leaves the latent untouched through all three steps and returns the encode and decode chain alone, the ceiling for every copying metric.

## Copying

Each output is compared with the anchor it started from, at 0.6 s, on four measures: CLAP audio cosine; correlation of z-scored 64-band log-mel patterns (10 ms frames, 80 dB range); waveform correlation, normalised by both clip energies; and correlation of the 5 ms RMS envelope at a 1 ms hop. The last three take the best lag within 50 ms (`--max-lag-ms`). Three nulls give the scale. Replay against its anchor shows what pure replay scores. Plain generation of the same key and seed against the same anchor shows what an output scores when the anchor had no influence. The nearest other library recording to each anchor shows how close two different real recordings get. An output counts as replay-like when its CLAP cosine and log-mel correlation both reach the 10th percentile of the replay null, and as plain-like when both stay under the 90th percentile of the plain null. Each output's CLAP embedding is also ranked against the whole library: the share whose nearest library clip is the anchor, and the anchor's median rank, say directly whether the output still reads as that recording.

Variants get the same treatment in pairs. Among the 20 seeds of a key, pairs from one anchor and pairs from two different anchors are summarised apart, beside plain pairs and pairs of the retrieved real clips. If same-anchor pairs come out as close as replay, the seeds collapse onto the anchor and the route gives five sounds per key however many variants it is asked for. Beside the copying numbers, the shape table gives per key the median attack time, tail length, noise floor and level 100 ms after the peak for the raw anchors, the replay, each level and plain, using `vocab_eval.shape_rows`. Those are the gunshot features the eval flagged, so the table shows directly whether a level inherits the anchor's attack and room or regresses to the model's. Under it, the static guard's verdict on every saved clip is printed per setting, starting with the raw anchors. The guard was tuned to catch generated hiss and noise beds, and real room tone at -40 dB is close to what it hunts; if it flags real anchors, it will retry anchored clips toward a drier result and undo part of the room-tone gain. The fake model in the dry run already trips it on 112 of 400 clips at level 0.5, so the real rate deserves a look before any judge number.

## Latency

Every clip is timed at batch 1 after warm-up, with a CUDA synchronize on both sides. For an anchored clip the time covers the anchor encode, sampling, decode, `_finish` and the static guard; for plain clips it covers `generator.generate`. Retrieval is timed separately per key as the CLAP text forward plus the cosine search over the library, median of five repeats. The report gives the steady cost per clip (retrieval cached per key) and the first clip of a new key (retrieval plus generation). Retrieval for a key nobody configured needs the CLAP text encoder resident next to the generator, which this run does not measure because it keeps one model on the GPU at a time.

## Output layout and scoring

Clips land in `data/_gate/anchor/<setting>/<event>-<material>_NN.wav`, the folder naming `vocab_eval.py` reads, for the 15 new-vocabulary keys plus footsteps on wood, stone, grass, metal and gravel (`vocab_eval.KEYS`). The settings are `s3_g1.0_k0.6` (plain, current), `raw`, `replay`, `anc_n0.5`, `anc_n0.7` and `anc_n0.9`. `settings.json` in the same folder records each setting with vocab_eval's four fields (`steps`, `detail_steps`, `gen_duration_s`, `duration_s`) plus the route, noise level and schedule, the anchor of every key and seed, the eval manifest and the library fingerprint. Every folder except the plain one also gets a `route.json` in the format `vocab_eval.py --route` reads: `clusters` lists every uploader and gun the setting anchored from (`fs:<uploader>`, `c3gd:<gun>`), `sources` the anchor files, and the rest records steps, prompts, the anchors per key, the noise level, the schedule and the caution. `--reuse` keeps any setting whose files, anchors and configuration match and loads no generator when all of them do. `scripts/bench/out_anchor_route.json` holds the pool, the retrieval lists, every per-clip copying row, the nulls, the pair summaries, the shape table, the schedules, the timings and the accelerator counters. `data/_gate/listen/anchor_route.wav` plays, per key and for the first two seeds, the raw anchor, its replay, each level and the plain clip.

`anchor_route.py score` runs `vocab_eval.main` with `--reuse --gen-dir data/_gate/anchor --settings s3_g1.0_k0.6` for the plain baseline and one `--route NAME=data/_gate/anchor/NAME` per other setting, against the manifest `settings.json` records, which is the held-out one whenever the sources file names it. vocab_eval then refuses any route whose `route.json` names a held-out cluster or shares an uploader, gun or file with a reference, and pairs each route with the plain baseline seed by seed, so the validated judges score the route with no generator loaded. Extra flags pass through to vocab_eval. `--manifest data/refs/manifest.json` scores against the old references, where vocab_eval prints the shared sources; there, 573 library clips are the very recordings the old references come from, so treat those numbers as leaked.

## Run command

The GPU run goes through `runpinned.py`, detached. Its cost is mostly CLAP: the vocab eval log shows 2987 s for 5316 clips, about 0.56 s per clip with its 60 texts, so the first run spends at most roughly that per library clip (under 50 minutes for the 5150-clip pool) plus about 15 minutes for the 1700 outputs. Generation (about 1700 model calls with the guard's retries) takes a few minutes, and a rerun skips the library pass.

```powershell
Start-Process -FilePath D:\Python\SAGE\.venv\Scripts\python.exe -ArgumentList '-u','D:\Python\sarge-research\modal\runpinned.py','D:\Python\SAGE\scripts\bench\anchor_route.py' -WorkingDirectory D:\Python\SAGE -RedirectStandardOutput D:\Python\SAGE\scripts\bench\anchor_route.log -RedirectStandardError D:\Python\SAGE\scripts\bench\anchor_route.err -WindowStyle Hidden -PassThru
```

It is finished when `anchor_route.log` ends with `saved -> D:\Python\SAGE\scripts\bench\out_anchor_route.json`. Then the judges, about as long as a full vocab eval (the reference clips dominate):

```powershell
Start-Process -FilePath D:\Python\SAGE\.venv\Scripts\python.exe -ArgumentList '-u','D:\Python\sarge-research\modal\runpinned.py','D:\Python\SAGE\scripts\bench\anchor_route.py','score' -WorkingDirectory D:\Python\SAGE -RedirectStandardOutput D:\Python\SAGE\scripts\bench\anchor_vocab.log -RedirectStandardError D:\Python\SAGE\scripts\bench\anchor_vocab.err -WindowStyle Hidden -PassThru
```

`--judges clap` after `score` gives a CLAP-only read in about a third of the time. `--keys "shoot|rifle" "break|window"` limits a probe to some keys, `--limit-library 500` subsamples the pool evenly for a smoke test, and `--schedules package scaled` adds the monotone schedule.

## Dry run

`anchor_review\dry_anchor2.py` in the session scratchpad runs `anchor_route.main` end to end with torch, torchaudio, transformers, stable_audio_3 and the other model packages blocked at the import system, and `validate_panel`, `recalibrate` and `ab_clap` stubbed by lifting their real functions with `ast`, as the vocab eval dry run did. The pool, the sources file, the PCM hashing, the audio processing and every copying metric run for real on the real datasets. CLAP is a fixed random projection of log-mel statistics, so similar audio lands close and text lands anywhere. The generator subclasses the real `StableAudio3Generator`, so `_prompt`, `_steps_for`, `_inputs` and `_finish` are the production code, and its fake model returns `(1 - sigma) * anchor + sigma * burst` when given `init_audio`, a known gradient for the copying metrics to recover. The fake judges answer for routes as well as settings. All 55 checks pass in 272 s.

The first half runs without a sources file, on the fallback pool and the old manifest. That pool came out at 3220 clips from 1091 sources: 3002 FoleySet train clips and 218 C3GD shots from the 14 DAVE guns left after holding out czusa_457, hk_P2000, marlin_gfm60, springfield_87A, springfieldd_xd and walther_ppk. Of 8556 candidates, 4329 went with held-out uploaders, 520 with recordings already in the eval manifest, 202 with uploaders of ESC-50 files, 124 with held-out guns, 112 with audio identical to a held-out or eval clip, 33 with Freesound recordings ESC-50 also holds, 9 as ai-generated and 7 as repeats inside the pool. Five synthetic sources files exercise the generic walk: nested usernames and platforms, train clusters that restrict and held clusters that exclude, an explicit pool resolved by path, id and C3GD filename (one of its three clips dropped for repeating test audio), clip records whose clusters and recordings become held sources, count maps, and a file with nothing recognisable, which stops the run. The checks then confirm one model on the GPU at a time (CLAP, generator, CLAP, each freed before the next loads); 401 plain calls, one replay call per distinct anchor, and 400 calls per level plus exactly the retries the guard reports; every `init_audio` a float32 44100-sample array at 44.1 kHz, byte-identical to its processed anchor; production sampler, cfg, padding, steps and duration on every call; seeds from `seed_for` or their static retries; prompts from `build_prompt`; anchor v mod 5 for every key and seed; six setting folders of 400 clips at 26460 samples with a `settings.json` vocab_eval accepts; and a raw folder within 1.5e-5 of the processed anchors. On the fake, the copying metrics fall with the noise level (log-mel 0.58, 0.44, 0.34 at 0.5, 0.7, 0.9), replay scores 1.00 and always finds its anchor as the nearest library clip, plain sits below level 0.5, and same-anchor pairs sit above different-anchor pairs. A `--reuse` pass loads no generator, reads 188 files (anchors and neighbours) where the first pass read 3408, and reproduces the copy summary exactly, and `anchor_route.py score` runs vocab_eval over the plain baseline and five routes with fake judges and no generator.

The second half uses the real sources file. The schema reader takes its 1433 training uploaders and 9 training guns, ignores `train_clips`, and builds the 5150-clip pool above, which the harness checks clip by clip against the CSVs. Asking that file for split val or the ALICE mic stops the run, and moving one held-out uploader (Anthousai) to the training side trips the pool leak guard. A full run on a 600-clip subsample of the pool returns with the held-out manifest recorded in `settings.json`, writes a `route.json` naming the 72 uploaders and guns behind its 82 anchors into each of the five non-plain folders, and `score` passes all five routes through vocab_eval's held-out leak check. Adding one held-out cluster to a `route.json` makes vocab_eval refuse to score.

The static guard flags 14 percent of the real anchors the fake retrieval picked in the first half (36 as hiss, 20 as bed) and 23 percent in the second (76 as hiss, 16 as bed). Those are the only numbers in the dry run about real audio and the guard, and they say the guard objects to a seventh to a quarter of real recordings before any model touches them. Every other copying, timing and retrieval number in the dry-run log comes from the fakes and means nothing.

## Known weaknesses

Retrieval quality rides on CLAP matching prompts such as "a shoot on rifle, dry, isolated sound effect" to real audio, and that grammar was tuned to steer generation; nobody has checked how well it searches. A key whose top five are the wrong object gets a confident, wrong sound at low noise, which is worse than a vague right one, so read the label shares before reading any judge number. Scores against the held-out manifest carry no source leak, at a price: its sets for door slams, gun mechanisms, pistol and shotgun shots and shell drops are thin (`thin_types` in the sources file), and its FoleySet footsteps hold 23 wood clips from 4 uploaders, 1 to 4 for stone, grass and gravel and none for metal, so a per-surface verdict rests on very few recordings. The old manifest gives fuller sets and leaks: 573 library clips are the recordings its references come from, and all 332 C3GD library clips share a gun with its pistol, rifle or shotgun references. A high judge score on `raw` or a low level there partly measures closeness to sources the judges were validated on. The copying thresholds come from nulls measured in the same run, which makes them relative: a route can be less replay-like than replay and still play the library back for practical purposes, and the listening file is the check on that. Multi-shot FoleySet sources reach the library through `_extract`'s loudest window, so a walking clip can hand a footstep key an anchor with two steps in it, and the 0.6 s comparison window will then score a two-step output against a two-step anchor as a match.

## Results, 2026-10-08

Anchoring helps the sounds the model was weakest at and hurts the ones it already made well, so it is a mixed route at every noise level. At noise 0.5 on the held-out judges, punch|body goes from 0.00 to 0.86 of real, shoot|pistol from 0.60 to 0.88 and explosion|grenade from 0.00 to 0.53, and footstep|metal rises from 0.07 to 0.36. Footsteps on wood drop from 1.00 to 0.81 and on gravel from 1.00 to 0.68, and click|button slips from 0.63 to 0.51. Breaking glass stays at 0.00 at every level, while the retrieved real glass anchors themselves score 0.77 of real: starting three Euler steps from half-noised real glass still loses the glass. Noise 0.7 is worse than 0.5 almost everywhere and 0.9 is close to plain generation, which the copy columns also show (CLAP to the anchor 0.55 at 0.5, 0.44 at 0.7 and 0.9, 0.44 for plain).

Shape moves only part of the way. At noise 0.5 the rifle tail grows from 114 to 270 ms and the pistol tail from 101 to 198 ms (the anchors ring for 313 and 289), but the attack gets slower, about 20 ms against 7 to 16 for plain generation and about 2 for the anchors, and the floor stays near -75 dB against the anchors' -44: the "dry, isolated" prompt cleans the anchor's room away. The static guard objects to 7 percent of the real anchors and pushes the anchored arms into retries (54, 151 and 54 retries per 400 clips at 0.5, 0.7 and 0.9; see the guard doc's limits).

Two numbers in the first report are void. The replay null came out silent because `init_noise_level` 0.0 makes the sampler return NaN for every clip, so its copy thresholds mean nothing; replay is now a direct encode and decode through the pretransform, and a rerun is queued. The silent replay clips also scored 1.23 of real on the door_open CLAP judge, which exposed a judge that accepts silence; `vocab_eval.py` now holds every judge to real minus silence of at least the gap, and the anchor scores are being redone with that control. Until then the door_open rows (0.12 plain, 0.86 at noise 0.5) carry no weight.
